## 5. Decision gates

1. **Mark vs exclude "stopped responding" — recommend mark; Chau confirms.** Checklist L118 allows either. Marking keeps the list at the invite limit, makes "required"'s cost visible (the lesson), and needs only a chip — `non_responding` is already on `TeamProfileRow`. Excluding would shrink `rankable_set` — dropping them from *every* list, moving `unrankable_profile_count`/composition numbers, and shrinking round-two's invitable pool — a much wider blast radius.
2. **`invited_without_card` derivation — recommend the base-field rule** (`invited ∩ stated_interests is None`), computed identically pre- and post-refresh; provably equals `invited_without_a_card`'s pre-refresh result because overlay cards only land on base-no-card profiles. No stored state, no identity exposure.
3. **Before/after over all rows — recommend the ingest-aligned row predicate** (not `rankable_set`): matches "all 300", matches the upload report Ann already verified (70/64/166, progress L13), costs no extra read (`list_team_profiles` is already loaded).
4. **Singular vs list mark** — recommend `refresh_marks: list[str]` (values `new_card`/`new_event`/`stopped_responding`): plan groups provably overlap (`_overlay_upsert` docstring :628-636; a no-card attender is in two draws). A single-valued field forces a precedence rule that hides information Ann asked to see.
5. **Second-press words — recommend client-composed** `"Already refreshed at {local time}"` from `refreshed_at`; server keeps `exercise_already_refreshed` + static "asked" sentence. Sub-decision: checklist's word is "refreshed", product voice is "asked" (`asking_wording.py:1-10`) — pick one and record it in §11.1.
6. **Choice-gate refusal code** — reuse `exercise_no_first_round_results` (message already fits) vs a new code for telemetry. Gate *after* `_choice_or_refusal` to keep `exercise_asking_choice_unknown` at 422 for unknown strings.
7. **Round-one event name for the "went to X" chip** — client `readEvents` probe (zero contract change; pattern already exists at `ExerciseAskingForMore.tsx:99-101`) vs a server field on `RankedListView` (kills a request on every list screen). Either is defensible; the client read is the smaller diff.
8. **`RefreshView` shape** — nest a shared `counts: RefreshCountsView` + `refreshed_at` (one shape for GET and POST, #330-friendly) vs flat additive fields (smaller diff, asymmetric with GET). Recommend nested — the contract isn't exported to OpenAPI, so the breaking change is contained to `exerciseClient.ts` + two screens.

## 6. Acceptance criteria

- POST `/refresh` 200 response carries `refreshed_at` and enough counts to render the checklist sentence verbatim ("N people who came to <round-one event>…; K of M invited people with no card completed one; J stopped responding").
- GET `/asking-choice` returns `refreshed_at` (null pre-refresh), the denominator, and before/after marker counts across **all** dataset profiles whenever `refreshed` is true — identical after a reload and for an instructor-refreshed team (M2 B4 pattern, `test_exercise_asking_counts.py:93-114`).
- The asking screen shows the timestamped summary, the before→after "Completed card 70 → 82"-style strip, and the shut state "Already refreshed at <time>" — persisting across reload.
- POST `/asking-choice` before round-one results → 409 `exercise_*`; the cards render disabled with a reason before that point.
- Ranked lists carry per-entry refresh marks; a profile may carry more than one.

## 8. Risks

- **Denominator drift on GET**: `invited_without_a_card` on a *post-refresh* view undercounts — overlay cards now read as cards. The reported denominator must read base fields only (§5.2). Pin it: same number in POST response and every later GET.
- **"All 300" vs rankable**: `_composition_for`'s all-profiles side is rankable-only (matching_models.py:639-648, pinned at `test_exercise_matching_router.py:556-575`). Reusing it for before/after would undercount on any file with major-less rows and contradict the ingest report; use the all-rows predicate — on Ann's file the answers coincide anyway.
- **Hidden-value handling**: copied-card *existence* is what marks/counts expose — already implied by the marker the team sees (`completed_card` post-refresh, checklist §7 L117). No card *content* beyond what the overlay already legitimately shows the owning team may be added; `refresh_marks`/counts touch only `overlay_*` columns. `copied_cards` stays the one reader (`results_cards.py:60-127`).
- **One-refresh semantics**: `refreshed_at` is claimed before overlays (`results_repository.py:566-580`) — the timestamp surfaced is the claim instant, identical for all teams under refresh-all (`instructor_refresh.py:128`) — a feature: one button, one moment.
- **Test churn from the choice gate** is the largest mechanical risk — seven test sites listed in §4, all mechanical (run first or seed `fakes.results.choices`).
- **`refreshed_at` timezone**: stored tz-aware UTC (`schema.py:95`); "10:42 AM" is the reader's local wall time — format client-side; never render UTC to a projector.
- **Stale local state**: `refreshed` bridge state in `ExerciseAskingForMore.tsx:182-191` must be superseded by server truth on reload — the existing "reset clears them" test (:481-516) already guards the pattern; extend it for the new fields.
- **Wording scan**: a `message=`/`refusal=` literal containing "refresh" anywhere in `exercise_*.py` fails `test_no_exercise_sentence_says_refresh` — write the checklist's "refreshed" wording client-side or get the scan amended with an explicit reason.
