## 5. Decision gates — recommendations

1. **Required vs optional column.** **Recommend required** (`event_columns` + `EXERCISE_LAYOUT`), contingent on committing the Oct-2 fixture in the same PR. Basis: every column the parser reads is required today (`event_date`/`info_level`/`events_attended_count` are *not read* and deliberately not on the layout — `layout.py:20-25`); Ann's own checklist (progress doc line 56, checklist §2 line 36) asks for the missing-column refusal to be demonstrated. The Sept workbook becomes the `missing_columns` test case. If the Oct-2 file cannot be committed yet, ship optional and tighten later — but note the `KeyError` guard needed in `_Cells` for the absent-column path.
2. **Where the text lives on responses.** **Recommend `description: str | None` on both `EventView` and `InstructorEventView`** (same public paragraph both audiences — checklist §3a shows the *same* description to teams and instructor) **plus `event_description` on `RankedListView`** so ExerciseMatching renders it without a second request. The "why someone would come" notes get **no field anywhere** — they're checklist prose, not workbook data (verified: the workbook cell holds only the public text). Do not create a second instructor-only field; nothing to populate it.
3. **Old-dataset behavior.** **Nullable `TEXT` column, `None` end-to-end, conditional render** — the `license_line`/`tiebreak_order`/`is_exploratory` precedent. A pre-0044 dataset simply shows no description; upload+re-point is Ann's stated mechanism for changing text. Blank past-event cells → `None` → nothing rendered; no special-casing `is_exercise_event` on the read path (picker already splits on `is_exercise_event`).
