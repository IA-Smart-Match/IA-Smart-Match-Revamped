# Issue #331 — Reset seed behavior: checklist §8 requires the same result after clearing

## 1. Stakeholder requirement (quotes + doc §)

- Checklist §8, `SmartMatch_User_Test_Checklist_10022026.txt:122-128`: clear one team → other teams unchanged → "rerun same list" → **"The result is the same as before (the chance part is fixed per team)."**
- Checklist §5, `:97`: "Each team's result is fixed and repeatable."
- Checklist §8 also requires warnings when a team switches to a new data file (`:122-128`).
- Current code/spec deliberately do the opposite: `workspace_repository.py:490-493` argues regeneration is "the one thing a reset in a classroom is for" — a design choice the checklist now contradicts.

## 2. Verified current state (file:line)

- `smartmatch_persistence/exercise/workspace_repository.py:480-550` — `reset_team()` deletes the target workspace's `exercise_profile_overlay`, `exercise_saved_setting`, `exercise_result_run`, then updates `seed=new_workspace_seed()` (`:546`), `asking_choice=None`, `refreshed_at=None`. Isolated to one workspace row.
- Seed generation: `smartmatch_domain/exercise/workspace_token.py:142-153` — `secrets.randbits(63)`; used at creation (`workspace_repository.py:280`) and on reset.
- Callers: instructor reset route `routers/exercise_instructor.py:532-588` (behind `require_instructor_session` + `X-Exercise-Request` header); repo wrapper `instructor_repository.py:549-590`; repoint path `instructor_repository.py:592-732` (seed regen at `:723`). `reset_workspace_children` (`:479-547`) is the child-delete shared by both.
- Pinned tests expecting a **new** seed: `tests/integration/test_exercise_workspace_persistence.py:489-534` (`:521` asserts `!=`); `test_exercise_full_class_run.py:461-469` ("gave it a new seed"); `test_exercise_instructor_persistence.py:234-252` (repoint regenerates).
- Determinism test to preserve: `test_exercise_full_class_run.py:413-416` proves seed changes the result; `:419-438` proves same-seed rerun equality. Driver `_reset_and_repeat` at `:232-271` (`set_seed` restore `:242-247`).
- Simulation: `smartmatch_domain/exercise/simulation.py` — `_uniform`/`_outcome` (`:503-518`, `:558-581`) digest `seed`+`event_key`+`profile_no`+purpose via `determinism.stable_digest` (`:37-50`); docstring `:108-138` documents the deliberate **SHA-256 deviation from spec §11** — never folded back into the spec.
- Stale spec text: `docs/superpowers/specs/2026-09-16-class-exercise-design.md:317-318` — still says `random.Random(seed ^ hash(event_key))` **and** "a team's reset … regenerates its seed." Both clauses need one edit.
- Runbook: `docs/operations/exercise-hosting.md:652-658` says reset "regenerates its seed"; step 19 `:994-998`. Schema comment `schema.py:262-265` says "fixed per team" — already consistent with keeping the seed.

- No test expects old-seed preservation anywhere; all three pinned assertions are one-line flips.

## 3. What must change / decision framing

1. **Option 1 — Keep seed on reset (recommended).** Delete `seed=new_workspace_seed()` at `workspace_repository.py:546`; rewrite the rationale docstring `:481-493`; flip the `!=`→`==` assertions; amend spec §11 and the runbook. Decide separately whether repoint also keeps seed — recommend yes (`instructor_repository.py:723`, test `:234-252`, docstrings `:592-598`, `exercise_instructor.py:316`). Semantics on dataset change: same seed with new `event_key`/`profile_no` values yields different draws via the digest — deterministic and data-driven; for an identical re-uploaded file the results are identical, which *strengthens* "fixed per team."
2. **Option 2 — Keep regenerating; get Ann's written change to checklist §8.** Zero code churn; fails §8 as written; risks a mid-review finding.
3. **Option 3 — Split actions.** "Clear team's work" keeps seed; new "Re-roll chance" regenerates. New route/UI/decision surface — overkill before Oct. 16.

Driver fix under Option 1: `test_exercise_full_class_run._reset_and_repeat:249-253` must recompute with a deliberately different seed (`old.seed + 1`) to keep `test_the_seed_changes_the_result` meaningful; `set_seed` restore becomes a no-op.
