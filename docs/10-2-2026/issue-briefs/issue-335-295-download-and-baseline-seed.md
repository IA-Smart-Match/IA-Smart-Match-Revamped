# Issue #335 — exercise: list download — plain "how much we know" column, plus a pink-column negative test

## 1. Stakeholder requirement (quotes + doc §)

- **Checklist §4 "Download"** (`docs/10-2-2026/extracted/SmartMatch_User_Test_Checklist_10022026.txt:83`): *"Download the list. The file opens in Excel with rank, name, major, year, how much we know, and the reason for each name. The two pink columns from the data file do not appear."*
- **Ann's progress doc** (`docs/10-2-2026/extracted/SmartMatch_Progress_and_Revisions_10022026.txt:58-60`): *"the two pink columns on the Profiles sheet hold each profile's true interests and true career goal. The app must never show them and never use them to build a list"* and *"Danny: the list participants download from the app must leave out the two pink columns. Justin: please check this."*
- The pink columns in Ann's xlsx are literally named `hidden_true_interests` / `hidden_true_career_goal` (`domain/exercise/layout.py:168-169`) — identical to the DB column names, so asserting those names absent covers "pink headers."

Optionally rename `CSV_LIST_COLUMNS` docstring/comment.
3. **Route** (`exercise_matching.py:484-490`, optional): encode body as `utf-8-sig` bytes — `content=ranked_list_csv(view).encode("utf-8-sig")` — so Excel detects UTF-8. BOM lands at byte level, before no cell value; the formula guard needs no change.

# Issue #295 — decision: "email everyone" baseline — per-team seed or one class-wide draw?

## 1. Stakeholder requirement (quotes + doc §)

- **Backlog row, verbatim** (`docs/plans/backlog.md:20`): *"'Email everyone' gives a different result for each team | Class-exercise orchestrator handoff, 2026-09-26 (LOW follow-ups, PR #241) | Class-exercise scope. The 'email everyone' panel is run with the team's own seed (`exercise_results_run.py`, one seed for both panels) so it is a fair comparison with that team's list, but two teams see two different 'email all 300' outcomes for the same event. Decide whether the baseline should be one class-wide draw. Needs Ann's view. No owner named."*
- **Requirements, Comparison row** (`docs/product/class-exercise-requirements.md:203`): *"The results screen always shows the 'email everyone' result (all 300 contacted) next to the team's result…"* — silent on seed sharing.
- **Checklist §5** (`…Checklist_10022026.txt:94-97`): baseline must sit beside the team's numbers, labelled "Email everyone (all 300)"; *"the two teams can differ a little because of chance"* — Ann expects per-team variation in **team** results; she does not say baselines should differ.
- Oct-2 audit (`docs/10-2-2026/SmartMatch_Oct02_Stakeholder_Audit_and_Opus_Prompt.md:57`) already flags #295 as the open seed decision.

## 2. Verified current state (file:line; flag stale claims)

- **"Team's own seed" — verified.** `exercise_results.py:253-262` → `run_the_rule(seed=team_state.seed)`; `exercise_results_run.py:283` calls `run_email_everyone(everybody, simulation, seed=seed, …)` — the *same* `seed` argument as `simulate_results` (`:270-276`). `run_email_everyone` docstring states the intent: *"a profile on both lists has the same outcome in both"* (`simulation.py:647-661`).
- **The published contract documents the choice**: `ResultsView.email_everyone` field description — *"the same rule with the same seed, so the two panels are comparable rather than two different simulations"* (`exercise_results_models.py:355-361`).
- **Seed lifecycle**: drawn by `new_workspace_seed()` = `secrets.randbits(63)` (`workspace_token.py:142-153`), stored `exercise_team_workspace.seed` (`schema.py:266`), read only via `results.team_state` (`results_repository.py:274-299`), **regenerated on reset** (`workspace_repository.py:546`) and on re-point to a new dataset (`instructor_repository.py:723`).
- **Draw scheme**: `_uniform(seed, event_key, profile_no, purpose)` → length-prefixed SHA-256 (`simulation.py:503-518`, `determinism.py:37-50`); per-profile draws are order-independent (`simulation.py:129-132`).
- **Stored, not recomputed**: `exercise_result_run.email_everyone` JSONB (`schema.py:415-418`); both POST and GET render the stored row (`stored_results_view`, `exercise_results_models.py:481-506`; `read_results` docstring: *"a record, not a recomputation"*). A seed-policy change affects only future runs; no migration needed.
- **Gap in the issue's framing**: the baseline's *inputs* are also per-team, not just the seed. `run_the_rule` injects this team's `non_responding` set into `everybody` for **both** panels (`exercise_results_run.py:264-267`, docstring `:259-261` — "so §13's cost under `required` shows up… in what 'email everyone' would have got"). So even with a class-wide seed, two teams' round-two baselines can still differ if their `required`-choice silenced different profiles. Full class-wide identity needs **both** a shared seed **and** team-independent inputs.
- Screen side: chart label "If you emailed everyone", caption "contacting all 300" (`ResultPanels.tsx:39,105-109`); checklist's "Email everyone (all 300)" label is a separate copy gap, not this issue.

## 3. What must change — ordered per layer (if Option B chosen)

Update the module docstring (it is the plain-words statement Ann receives — `:12-27`, behaviours `:48-54`, `run_email_everyone` docstring `:654-660`).
2. **API** (`exercise_results_run.py:263-295`): pass baseline seed to `run_email_everyone`; if full identity is wanted, build `everybody` twice (with/without `silent`).
3. **Contract text** (`exercise_results_models.py:355-361`): reword the field description.
4. **Tests**: see §7 — three pinned tests invert under B.
5. **Records**: resolve the backlog row (its header requires a plan/ADR/register row to move it); amend design-spec text (§10 "same seed", `docs/superpowers/specs/2026-09-16-class-exercise-design.md:287-288`).

## 4. Impact radius

- Team panel, refresh, asking — **unchanged** (still team seed: `exercise_results.py:483`, `workspaces_awaiting_refresh` `results_repository.py:332-370`).
- Stored `email_everyone` panels on existing rows unaffected (stored-as-written).

## 5. Decision gates with recommended options

**Option A — keep per-team seed (status quo).** Within a team's screen, a shared profile has one outcome across both panels — the comparison is *who was asked*, not two simulations (`simulation.py:656-660`; `test_exercise_results_panels.py:81-98`). Cost: two teams project different "email all 300" numbers for the same event — the confusion the backlog row names; a reset team's baseline also changes with its new seed.

**Option B — one class-wide baseline.** Two sub-decisions:
- *B-i (seed only)*: minimal diff; round-one baselines become identical, round-two baselines can still diverge via per-team `non_responding` — half-fix.
- *B-ii (seed + team-independent inputs)*: baseline is a true fixed target per (dataset, event); every team's panel reads identically. Side benefit: under `required`, the baseline *doesn't* pay the team's asking cost — arguably the sharper lesson ("you asked too hard; plain mass email beats your list"). Cost: a profile on the team's list can "sign up" in one panel and not the other — the property the current code, contract text and tests all document is deliberately traded away; `run_email_everyone`'s docstring and the ResultsView description must be reworded.

**Recommendation to send Ann**: **B-ii**, seeded deterministically from the dataset checksum via `stable_digest` (no new constant; changes with the file the way the fixed order does). Rationale: the baseline's job is a *reference point for class discussion* — Ann walks between six projectors and wants "email everyone" to be the same number everywhere; the within-team apples-to-apples property A buys is invisible anyway (the everyone panel shows counts only, never names — `ResultPanels.tsx:13-15`). Present A as the fallback: if Ann values "identical luck for your 30 vs all 300" over a shared target, keep it — the cost of staying is only the backlog row's confusion, already documented.

**Adjacent conflict to raise in the same question**: checklist §8 expects a cleared team's rerun to give "the result… the same as before," but `reset_team` regenerates the seed (`workspace_repository.py:490-493` — deliberate: "the one thing a reset in a classroom is for"). The integration walk satisfies the checklist only by restoring the seed via `set_seed` (`exercise_class_driver.py:242-247`). Under B the baseline at least stays fixed across resets; the team-result expectation still conflicts with seed regeneration and deserves a word from Ann.
