# CBA phase deferral and decision register

**Status:** Active planning gate  
**Customer source:** [`docs/product/cba-smart-match-customer-requirements.md`](../../product/cba-smart-match-customer-requirements.md) §§20, 21, 25, 26  
**Applies to:** The CPP CBA pivot only. It does not delete prior IA-West work or authorize live providers.

This register is the fail-closed boundary for the CBA phase. Unresolved product choices are recorded here instead of becoming permanent implementation defaults. Gated capabilities remain in the repository but are not mounted, routed, advertised, or presented as successful on CBA paths.

### OQ-CBA-004 decision record requirements

The decision must cite [`docs/architecture/decisions/ADR-0011-accountable-numbers.md`](../../architecture/decisions/ADR-0011-accountable-numbers.md) and answer both cases separately:

1. Missing Topic evidence: whether “neutral” is an explicit customer policy value with distinct provenance or still an unknown value excluded from scoring.
2. Virtual events: whether excluding Proximity is a conditional factor registry, an approved normalization rule, or another versioned policy.

The approved artifact must define serialization, UI labeling, match-run pins/fingerprints, and golden cases. Approval must precede edits to [`python/smartmatch_domain/smartmatch_domain/factor_registry.py`](../../../python/smartmatch_domain/smartmatch_domain/factor_registry.py).

#### Drafting status, and what the owner must still approve

Its status is **Proposed, not Accepted**, and it records no decision date and no signature, because the named owner has not decided. A drafted proposal is not an approval, and the question below stays **Open — awaiting owner decision**:
