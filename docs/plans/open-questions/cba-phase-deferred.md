# CBA phase deferral and decision register

**Status:** Active planning gate  
**Customer source:** [`docs/product/cba-smart-match-customer-requirements.md`](../../product/cba-smart-match-customer-requirements.md) §§20, 21, 25, 26  
**Applies to:** The CPP CBA pivot only. It does not delete prior IA-West work or authorize live providers.

This register is the fail-closed boundary for the CBA phase. Unresolved product choices are recorded here instead of becoming permanent implementation defaults. Gated capabilities remain in the repository but are not mounted, routed, advertised, or presented as successful on CBA paths.

#### Drafting status, and what the owner must still approve

[`ADR-0016-cba-scoring-policy.md`](../../architecture/decisions/ADR-0016-cba-scoring-policy.md) drafts every one of those fields. Its status is **Proposed, not Accepted**, and it records no decision date and no signature, because the named owner has not decided. A drafted proposal is not an approval, and the question below stays **Open — awaiting owner decision**:

| # | ADR-0016 proposal | What Danny Tran must approve, amend, or reject |
|---|---|---|
| 1 | Third evidence state | That `policy_neutral` (an observed absence of usable topic evidence) is a distinct state from `unknown` (evidence that could not be evaluated), and that only the latter makes the composite unknown. |
| 2 | Neutral value and provenance | `CBA_NEUTRAL_TOPIC_VALUE` = `0.50` (or `0.40`, or another value), plus the policy id, policy version, and the `basis` wording a Speaker Connector reads. |
| 3 | Proximity band sub-scores | `1.00` / `0.60` / `0.20`, as a step function, and that exactly 25 miles is Mid and exactly 75 miles is Far (lower-inclusive, upper-exclusive). |
| 4 | Missing address | That an unknown distance is `unknown` and not the far band, accepting that such candidates are unscorable and sort last. |
| 5 | Virtual events as a scoring mode | That excluding Proximity is a named, pinned scoring mode (`cba-physical-1` / `cba-virtual-1`) rather than a conditional registry. |
| 6 | Virtual redistribution formula | Proportional renormalization (`0.428571` / `0.357143` / `0.214286`) **or** a fixed table such as `0.40` / `0.35` / `0.25`. |
| 7 | Serialization | That a stored score states which of its factors were policy values, via `policy_neutral_factor_keys`, `policy_id`, `policy_version`, `scoring_mode`. |
| 8 | UI labels | The seven coordinator-facing strings, especially the neutral-Topic label. |
| 9 | `REGISTRY_VERSION` pin policy | That adopting 1–8 is a major bump to `2.0.0-approved-oq-cba-004`, and that runs pinned to `1.1.1-approved-g1-m6j` are retained but never compared across the bump. |

## Enforcement expectations for Wave 0

Planning assumes one explicit `PRODUCT_PHASE=cba`-style capability policy (exact representation to be chosen during implementation) shared by API composition and frontend navigation. Tests must prove gated CBA routes/links are absent or return a truthful disabled response, while preserved consented outreach, event reads, discovery feed, and one backend-derived login flow remain available.

`ALLOW_LIVE_PROVIDERS=false`, `ALLOW_LIVE_DATA=false`, and `ALLOW_CLOUD_DEPLOY=false` remain mandatory defaults. This document authorizes no code or environment change.
