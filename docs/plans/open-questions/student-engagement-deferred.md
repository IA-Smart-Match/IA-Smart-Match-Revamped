# Student engagement — canonical open-question and blocker register

**Status:** canonical decision register, created 2026-09-14. Every row is
**OPEN — tentative-development**. A safe default prevents unauthorized behavior;
it is not a product decision. This document closes no OQ-CBA, OQ-E, D, S, or
student-engagement decision.

**Program:** [`../2026-09-14-student-engagement-program-plan.md`](../2026-09-14-student-engagement-program-plan.md).
Older briefs and W1–W4 plans may cite these IDs only as historical evidence; this
file is the sole authoritative student-engagement register.

Closure requires an attributed, dated decision artifact plus the evidence named in
the row. Internal CBA development does not require legal sign-off, but it does
require the named privacy, records, accessibility, security, program, and operations
owners. Legal review is a later gate before external deployment, public release,
cross-unit expansion, or live-provider/live-data use.

## Closure discipline

- Do not reuse an OQ ID for a different decision. In particular, OQ-SC-09 does
  not approve `STUDENT_REGISTRY_VERSION`.
- Do not close a student row by implication from an OQ-CBA or OQ-E row. Record the
  cross-reference and the separate student-engagement disposition.
- A schema decision authorizes no fixed migration number. The migration-queue
  owner assigns current-head-plus-one at merge readiness, after rebase, preserving
  one head.
- Safe defaults remain active until closure evidence lands. A plan, prototype,
  feature flag, or unwired implementation is not closure evidence.
